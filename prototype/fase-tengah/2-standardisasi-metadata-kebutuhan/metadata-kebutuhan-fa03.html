Matriks Spesifikasi Kebutuhan Fungsional (Functional Requirements)

Daftar fungsi sistem yang wajib dibangun oleh tim pengembang perangkat lunak berdasarkan proses bisnis Dinkes.

REQ-F-01 Validasi & Entri Rujukan Pasien di Puskesmas (FKTP)
Role: Petugas Puskesmas / Dokter Pemeriksa

Sistem harus mampu menarik data kependudukan pasien secara otomatis melalui NIK (integrasi JSS Dukcapil) dan memvalidasi kepesertaan jaminan BPJS Kesehatan secara real-time via BPJS PCare API sebelum surat rujukan elektronik diterbitkan.

Prioritas: Tinggi (Must Have) Kriteria Keberhasilan: Durasi penarikan NIK ≤ 1.5 detik, auto-fill nama, alamat, faskes induk. Modul: Modul Intake Rujukan FKTP
REQ-F-02 Pemberitahuan & Triase Terpadu Tim IGD / Spesialis RSUD
Role: Dokter Spesialis / Perawat IGD RSUD

Sistem harus menampilkan notifikasi suara dan visual peringatan rujukan darurat (Emergency Red Tag) di ruang IGD RSUD Yogyakarta, serta memungkinkan dokter spesialis memberikan advis awal (tindakan stabilisasi pra-rujukan) langsung melalui aplikasi sebelum pasien tiba.

Prioritas: Tinggi (Must Have) Kriteria Keberhasilan: Push notification WebSocket latency ≤ 500ms, tombol konfirmasi respons satu ketukan. Modul: Modul Triase & Advis Gawat Darurat
REQ-F-03 Live Dashboard Kapasitas Bed & Ruang ICU/NICU Terkini
Role: Operator Call Center PSC 119 & Publik

Sistem harus menyajikan matriks live bed availability terintegrasi dengan SIMRS RSUD Jogja, memetakan ketersediaan ranjang isolasi, ICU, HCU, perinatologi secara berkala per 5 menit tanpa intervensi manual petugas.

Prioritas: Sedang (Should Have) Kriteria Keberhasilan: Sinkronisasi API dua arah tanpa lag dan tersedia widget publik di JSS Mobile. Modul: Modul Integrasi SIMRS Bed Monitoring
REQ-F-04 Pelacakan Status Rujukan Mandiri oleh Pasien & Keluarga (via JSS)
Role: Pasien / Masyarakat Kota Yogyakarta

Pasien atau keluarga yang memiliki akun Jogja Smart Service (JSS) dapat memantau estimasi nomor antrean, jadwal dokter poli spesialis yang dituju, dan estimasi waktu penanganan rujukan langsung dari ponsel pintar mereka.

Prioritas: Menengah (Nice to Have / Fase 2) Kriteria Keberhasilan: Antarmuka ramah ponsel dengan integrasi Single Identity JSS. Modul: Modul Portal Warga JSS Gateway

Standar Kebutuhan Non-Fungsional (Non-Functional Requirements)

Parameter performa, keandalan teknis, ketahanan siber, dan infrastruktur pusat data Pemkot.

Dimensi NFR Parameter / Target Metrik Spesifikasi Implementasi Tim Pengembang Tingkat Kritis
Ketersediaan & Keandalan (Availability) SLA ≥ 99.5% (Downtime maks. 3.6 jam/bulan) Dijalankan pada klaster containerized OpenShift/Docker Swarm Data Center Diskominfo Kota Yogya dengan load balancing Nginx redundant. Mission-Critical
Kecepatan Tanggap (Response Time) Waktu respons API ≤ 1.5 detik pada 95th percentile Optimasi query database PostgreSQL, implementasi Redis Caching untuk ketersediaan bed, dan kompresi payload GZIP. Tinggi
Beban Pengguna (Concurrent Users) 1.000 concurrent sessions tanpa degradasi memori Kapasitas alokasi server awal: 4 vCPU, 8 GB RAM, auto-scale horizontal hingga 3 replicas saat lonjakan wabah musiman. Sedang
Keamanan & Kelaikan Siber (Cybersecurity) Zero High/Critical Vulnerability (OWASP Top 10) Enkripsi TLS 1.3, proteksi CSRF, Content Security Policy (CSP), proteksi injeksi SQL via ORM Prisma/TypeORM, dan mandatory Pentest sebelum rilis. Wajib Pentest
Pencadangan & Pemulihan (Backup & DR) RPO ≤ 1 Jam, RTO ≤ 4 Jam Automated snapshot harian MinIO Object Storage Pemkot, cadangan database off-site ke Data Center Sekunder Giwangan. Penting
Kepatuhan Regulasi & PDP UU No. 27/2022 (PDP) & Permenkes Audit trail terenkripsi untuk seluruh akses rekam medis rujukan; pencatatan IP, waktu, identitas dokter pengakses yang tidak dapat diubah (immutable log). Mandatori

Matriks Mitigasi Risiko Ketergantungan Eksternal

Risiko 1: Kegagalan API BPJS PCare (Downtime Nasional)

Mitigasi: Sediakan antrean asinkron (Message Queue RabbitMQ/BullMQ) dengan fallback mode darurat offline kartu fisik BPJS, sehingga rujukan pasien gawat darurat tidak boleh tertolak di loket IGD.

Risiko 2: Keterbatasan Bandwidth Internet di Puskesmas Pembantu

Mitigasi: Kompresi payload transmisi data, caching lokal browser (Service Worker PWA), dan prioritas rute VPN FO Pemerintah Kota Yogyakarta.
